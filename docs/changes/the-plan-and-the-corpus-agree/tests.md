# What will prove it

Assertions in `scripts/smoke.sh`, against a real corpus in a temporary directory.

## Writing an entry

**An entry can be written by command**, and **its name is minted by the same rule as every other
name** — `Облік expenses` is refused for the words it would lose, exactly as a change or a
capability would be. That is the half a hand-written file does not get.

**And it is numbered where the corpus asks.** `roadmap: '{ordinal:4}-{slug}'` produces
`0001-a-thought`.

**A capability it does not have is refused**, and **a duplicate is refused** — the same two
refusals `capability new` makes, for the same reasons.

## The link

**A change may name what it realises**, and it appears in `--json`.

**An entry that is not there is refused** at creation, naming the entries there are.

## The disagreement

**A realised entry is reported.** The change publishes, the entry survives, and `molly status`
says which change realised it and that it should be retired. This is the failure the whole change
is for.

**And the corpus stays clean.** `ok: true`, because an entry is a note rather than a governed
unit, and failing a build over a planning document nobody retired would be refusing somebody's
notes for existing.

**Retiring it quietens the report** — asserted rather than assumed, because a finding that never
goes away is one people learn to ignore.

**A published change is not asked again.** After the entry is retired, the archived change points
at nothing and *that is correct* — reporting it would turn every correct publication into a
finding.
