# What will prove it

Assertions in `scripts/smoke.sh`, against a real corpus in a real git repository.

## The rule

**A trailer naming a change passes**, and **one naming nothing is refused** — the whole point,
said both ways.

**A required type with no trailer is refused**, naming the types that need one. **A type nobody
asked of passes** with no trailer at all.

**A corpus declaring nothing requires nothing** — and **still refuses a wrong trailer**. This
pair is the split the change is about: the tool imposing no convention, and still answering the
one question that is its own.

## What is not a person's to edit

**A merge commit is not asked.** Generated by git, no type, and requiring an edit to it is
requiring an edit to a message the tool wrote.

**A trailer in the comment block is not a trailer.** `# MollyGuard: real` is refused, because git
strips that block after the hook has seen it and the author never wrote the line.

## The past

**An archived change still resolves.** A `fix` naming a change sitting in `history/` passes. A
check knowing only what is in flight would start refusing the repository's own history the first
time anybody rebased over it.

## The hook

**It installs**, and **one already there is kept** rather than replaced — the courtesy `init`
gives a directory it did not make.

**It installs from a worktree.** `.git` is a file there, and joining a path onto it crashed with
`ENOTDIR` and exit `2` — the code reserved for a defect in the tool — while standing somewhere
entirely ordinary.

**Outside a repository it is a refusal, not a crash.** Exit `1` says the tool declined; exit `2`
says the tool broke, and the difference is the whole reason there are three codes.
