# The work, in order

Reading first, because everything after it is a consequence of what the reading found, and a
table built after the code is a table written to fit it.

1. **Re-read the twelve rows that exist.** Each against that vendor's own documentation, today.
   A row that was right when it was written is not a row that is right now, and the point of
   checking is to find the one that moved.

2. **Read the tools named in the roadmap's long tail.** Roo, Kilo, Junie, Qwen, Kiro, Goose,
   Continue, OpenHands, Augment — as far as their own documentation answers. What comes back is
   three kinds of answer: reads the shared root, reads its own directory, or contradicts itself.

3. **Add the rows the shared root already covers.** Goose, Roo Code, OpenHands. No new file is
   written; the change is that naming one of them works and the install says who it served.

4. **Add the two directories, and make them defaults.** `.junie/skills` and `.kiro/skills`, with
   the reason for defaulting stated where the default is declared — the alternative is a
   directory `--check` never looks at.

5. **Say what was refused, and why.** Kilo Code and Qwen Code stay out. The roadmap entry keeps
   the finding rather than the search, so the next person does not repeat it.

6. **Move the counts.** The default install is sixteen files, and the assertions that name a
   count are the ones that catch a directory added by accident.

7. **Assert the two absences.** `--tools junie` writes the JetBrains directory and not the shared
   root; the same for `kiro`. These are the rows most likely to be quietly corrected into the
   majority, and an absence is what catches that.

8. **Install them here.** This corpus runs `molly agents`, so its own four directories are what
   the change looks like from outside.
